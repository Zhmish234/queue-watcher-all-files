# Queue Watcher — мониторинг очереди Паспортного сервиса (Мюнхен)

Проверяет раз в час, появились ли свободные места в электронной очереди
на https://munich.pasport.org.ua/solutions/e-queue, и присылает уведомление
в Telegram, если места есть.

## Шаг 1. Создать Telegram-бота

1. В Telegram напиши **@BotFather** -> `/newbot` -> следуй инструкциям.
2. Получишь токен вида `123456789:AAExampleTokenXXXXXXXXXXXXXXXXXXXXX` —
   это `TELEGRAM_BOT_TOKEN`.
3. Напиши своему новому боту любое сообщение (например "привет"), чтобы
   он тебя "увидел".
4. Открой в браузере:
   `https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates`
   и найди в ответе `"chat":{"id": ЧИСЛО, ...}` — это `TELEGRAM_CHAT_ID`.

## Шаг 2. Загрузить проект на GitHub

1. Создай новый **публичный** репозиторий на github.com (публичный — чтобы
   Actions были бесплатны без ограничений по минутам).
2. Залей туда все файлы из этой папки (`check_queue.py`, `requirements.txt`,
   `.github/workflows/check-queue.yml`, этот README).

## Шаг 3. Добавить секреты

В репозитории: **Settings -> Secrets and variables -> Actions -> New repository secret**

- `TELEGRAM_BOT_TOKEN` — токен из шага 1
- `TELEGRAM_CHAT_ID` — chat id из шага 1

## Шаг 4. Проверить вручную

Вкладка **Actions** -> workflow "Check e-queue slots" -> **Run workflow**.
Посмотри логи: скрипт должен написать "Мест пока нет." или прислать
сообщение в Telegram.

После этого workflow будет запускаться автоматически каждый час.

## Отладка (если селекторы не сработают)

Сайт использует нестандартный (не `<select>`) выпадающий список, поэтому
я не могу на 100% гарантировать, что автоматический клик найдёт нужные
элементы с первого раза без возможности реально открыть сайт в браузере
с JS. Если в логах Actions видна ошибка вида
"Не удалось открыть выпадающий список" или "Не нашёл пункт..." —
сделай так:

1. Открой сайт в Chrome на компьютере.
2. Нажми `F12` (DevTools) -> вкладка **Elements**.
3. Наведи курсор на поле "Послуга" / кнопку "Обрати" и посмотри HTML-код
   этого элемента (класс, id, тег).
4. Пришли мне этот кусок HTML — я обновлю селекторы в `check_queue.py`.

## Важные ограничения

- GitHub Actions может запускать `schedule`-задачи с задержкой до
  15-20 минут в пиковые часы — это ограничение самого GitHub, обойти
  нельзя, но для проверки "раз в час" это не критично.
- Если репозиторий 60 дней без активности (коммитов), GitHub
  автоматически отключает scheduled workflows — тогда нужно будет
  сделать любой пустой коммит, чтобы снова включить.
- Скрипт **не пытается обойти капчу** и не пытается сам записаться —
  только проверяет статус и уведомляет тебя, чтобы ты сам успел
  записаться вручную.
